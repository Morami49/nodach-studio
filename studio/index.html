                Policies

                Studio is the source of truth for every approval policy (D-133, Q101 A). Executors read these; a platform's own copy (like GitHub's variable) is checked against Studio and flagged when it differs. Each change is a version on the tree.

                  Runs

                  Every automated run, from every executor, newest first (P-13): who started it, why (trigger and policy), what it changed, the outcome, and how to undo it. Runs from GitHub open on GitHub, where Re-run repeats them.

                    Usage

                    Nodach is free to use, with generous monthly limits on machine capacity: AI calls, flow runs and storage. Each profile and each teamspace has its own meter, counted per calendar month (UTC). At 80% the owner gets an urgent notice in My queue; at 100% AI calls and runs stop until the month ends ("Monthly free limit reached; a top-up will be available soon"). Storage only warns. Top-ups come later.

                        Developer mode
                        
      
                        
      
                        Develop Studio from Studio. A look or schema save is a proposal first (NVS-4); applied on staging, it becomes a version you can go back to (D-152). Anything that needs new code becomes a change request: once you approve it, the change-intake job turns it into a GitHub issue for whichever AI or person is building, and the result comes back through tests and a deploy you can see in Runs (D-149, D-153). Nothing here can break the record: Studio only reads these settings, it never rewrites history.
